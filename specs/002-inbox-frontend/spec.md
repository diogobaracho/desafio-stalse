# Feature Specification: Inbox Frontend

**Feature Branch**: `002-inbox-frontend`

**Created**: 2026-10-08

**Status**: Implemented

**Input**: "A web inbox where support agents list, search, open and triage tickets and see ETL metrics. Brazilian Portuguese by default with English available. White-label: brand and contact data come from a config file. Production is read-only."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Browse and search the inbox (Priority: P1) 🎯 MVP

**Acceptance Scenarios**:

1. **Given** the API returns tickets, **When** the agent opens `/tickets`, **Then** a table shows created date, customer, channel, subject, status and priority, each row linking to `/tickets/[id]`.
2. **Given** the agent types in the search box, **When** they pause typing (300 ms debounce), **Then** the list is re-fetched through the API with `?search=`.
3. While loading, a loading message is announced. With no results, an empty state appears. On an API failure, an error state with a retry action appears.

### User Story 2 - Triage a ticket (Priority: P1)

**Acceptance Scenarios**:

1. **Given** `/tickets/1`, **Then** every field is shown, plus selects for status and priority.
2. **When** the agent saves, **Then** the button is disabled while the request is pending, a success message is announced (aria-live) and the server-confirmed values are shown.
3. **When** the API fails, **Then** a translated error message is announced and the previous values are kept.
4. **Given** an unknown id, **Then** a not-found page with a link back to the list appears.
5. **Given** the API reports `read_only=true`, **Then** a banner explains that the environment is read-only and the controls are disabled.

### User Story 3 - Metrics dashboard (Priority: P2)

**Acceptance Scenarios**:

1. **Given** `GET /metrics` succeeds, **Then** cards show total records and invalid dates, and tables show records by day, top categories, channels and priorities, with a note that the data was generated by the ETL pipeline (including source and generation time).
2. Loading, error and empty states (for example `total_records = 0`) are handled.

### User Story 4 - Language selection (Priority: P2)

1. **Given** a first visit, **Then** the UI is in pt-BR.
2. **When** the user chooses English in the header switcher, **Then** the UI re-renders in English and the choice persists through a cookie.

### User Story 5 - White-label branding (Priority: P3)

1. **Given** `BRAND_CONFIG_PATH` points at a valid brand JSON, **Then** the product name, company, logo, colors, page title and footer contact information (email, phone, website, address) come from that file without a rebuild.
2. **Given** an invalid brand file, **Then** the app logs a clear error and falls back to the default brand.

### Edge Cases

- Status and priority are never conveyed by color alone (text plus icon).
- Fast typing does not trigger one request per keystroke, and stale responses never overwrite newer ones.
- Double-clicking Save sends one request.

## Requirements *(mandatory)*

- **FR-001**: Routes `/tickets`, `/tickets/[id]`, `/dashboard`; `/` redirects to `/tickets`.
- **FR-002**: All HTTP goes through `lib/api` (typed, non-2xx → `ApiError` with `code`).
- **FR-003**: The browser uses `NEXT_PUBLIC_API_BASE_URL`; server rendering uses `API_INTERNAL_BASE_URL` when it is set.
- **FR-004**: All user-facing strings come from `messages/{pt-BR,en}.json`, with pt-BR as the default.
- **FR-005**: All brand and contact data comes from the brand config (`config/brand.default.json` or `BRAND_CONFIG_PATH`).
- **FR-006**: Accessible markup: labels, a semantic table, headings, visible focus, aria-live status regions, WCAG AA contrast.

## Success Criteria *(mandatory)*

- **SC-001**: Component tests cover every acceptance scenario; line coverage ≥ 75%.
- **SC-002**: The E2E critical path (list → search → detail → update → dashboard) passes against docker compose.
- **SC-003**: Swapping the brand file changes every brand string. `grep` finds no brand or contact literal in `app/`, `components/` or `lib/`.

## Assumptions

- Desktop-first, but responsive down to 360 px. The table scrolls horizontally inside its container on small screens.
- No authentication (see the 001 assumptions).
